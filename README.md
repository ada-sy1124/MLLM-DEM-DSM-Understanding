# 🌳 核心架构：视觉思维树 (Visual Tree-of-Thought) 完整梳理

**核心理念**：彻底摒弃 VLM 传统的“隐式黑盒解码（直接输出最终坐标）”，强制模型在单次推理（Single-Pass）中，显式地构建一棵包含“规划、发散、排谬、收束”的搜索树，从而根除长文本多实体任务中的“空间幻觉”。

---

## 第一部分：推理流程 (Inference Pipeline)

*在测试或实际部署时，模型面对一张新图和一句长难句，必须严格遵循以下四步生命周期进行自回归输出：*

### 阶段 1：语义降维与层级规划 (Semantic Planning)

* **目的**：防止模型“看着图发呆”，强迫其先在纯文本层面对长难句进行逻辑拆解。
* **动作**：提取出“宏观锚点”、“中继约束”和“微观目标”。
* **输出格式 (`<plan>`)**：
```xml
<plan>
  层级 L1 [宏观锚点]: 四栋大厦 (提供全局定位范围)
  层级 L2 [中继约束]: 高架桥 (用于收束搜索空间)
  层级 L3 [最终目标]: 加油站 (精细定位)
</plan>

```



### 阶段 2：视觉广度搜索与候选生成 (Candidate Generation)

* **目的**：打破“单线思考”的局限，鼓励模型在早期寻找所有疑似的起始锚点，保证极高的召回率（Recall）。
* **动作**：视觉编码器扫描全图，输出多个疑似区域的坐标框。
* **输出格式 (`<step_propose>`)**：
```xml
<step1_propose>
  在全图中发现两处疑似“四栋大厦”的候选区域：
  <cand_A>[100, 200, 300, 400]</cand_A>
  <cand_B>[600, 100, 800, 300]</cand_B>
</step1_propose>

```



### 阶段 3：自我反思与逻辑剪枝 (Self-Verification & Pruning) 🔥 [核心创新点]

* **目的**：赋予模型“排谬”的物理直觉。不仅要知道什么是对的，还要能用逻辑自证什么是错的。
* **动作**：逐一检查阶段 2 提出的候选框，结合阶段 1 的规划条件进行验证。
* **输出格式 (`<verify>`)**：
```xml
<step2_verify target="cand_A">
  检查 <cand_A> 的右上角区域，未发现“高架桥”特征。
  结论：此分支废弃 (Pruned)。
</step2_verify>

<step2_verify target="cand_B">
  检查 <cand_B> 的右上角区域，成功提取到“高架桥”特征。
  中间坐标：<box_L2>[650, 150, 750, 250]</box_L2>。
  结论：保留此分支 (Proceed)。
</step2_verify>

```



### 阶段 4：终极精确锁定 (Final Target Grounding)

* **目的**：在排除了所有干扰项、且视野已经极度收束的情况下，进行难度极低的局部目标检测。
* **动作**：沿着正确的 `Proceed` 分支继续深入，输出最终答案。
* **输出格式 (`<final_box>`)**：
```xml
<step3_final target="box_L2">
  在 <box_L2> (高架桥) 的下方区域，锁定最终目标“加油站”。
</step3_final>
<final_box>[680, 180, 700, 200]</final_box>

```

## 第二部分：训练与对齐管线 (Training Pipeline)

*为了让基座模型（如 Qwen2.5-VL）掌握上述神仙级的思考方式，必须经历“两段式”的训练重构：*

### Step A：数据自动化逆向合成 (SFT 数据构建)

既然人类标不出几万条这么复杂的思维树，我们就用 Python 代码结合 API 自动化“伪造”黄金轨迹：

1. **逆推规划**：用 LLM (GPT-4o) 提取出 `<plan>` 里的三个层级。
2. **暴力召回**：用目标检测器 (Grounding DINO) 在图里把这三层对应的所有物体全框出来，作为候选池。
3. **几何溯源**：通过代码比对 Ground Truth 坐标，逆向计算出哪条路径是对的，哪条是错的。
4. **轨迹编织**：将正确的路径打上 `Proceed` 标签，错误的路径打上 `Pruned` 标签，封装成上文展示的 XML 格式喂给模型进行监督微调（SFT）。

### Step B：基于搜索树的过程奖励强化学习 (PRM-GRPO) 🔥

在强化学习阶段，摒弃只看最终 IoU 的粗放式打分，引入多维度的复合奖励机制（Reward Engine）：

* **1. 语义对齐奖励 ($R_{Plan}$)**：评估模型拆解的实体词是否与原指令匹配。
* **2. 探索广度奖励 ($R_{Recall}$)**：只要模型在 `<step_propose>` 里提出的候选框（无论对错）覆盖了真实目标的关联区域，就给予正向分数，鼓励它“多提假设”。
* **3. 剪枝排谬奖励 ($R_{Pruning}$) 【杀手锏】**：
* 如果模型成功识别出错误的 `<cand_A>` 并输出了 `Pruned`，**给予巨大奖励（+2.0）**。
* 如果模型把正确的框给剪枝了，**给予巨大惩罚（-2.0）**。


* **4. 终极精度奖励 ($R_{Final\_GIoU}$)**：评估最后输出的 `<final_box>` 与真实答案的几何交并比。

---

### 💡 核心优越性总结

通过这套机制，我们将原来极易崩盘的 **“长文本 $\rightarrow$ 绝对坐标”** 映射，巧妙地降维成了 **“短文本 $\rightarrow$ 局部搜索 $\rightarrow$ 排错 $\rightarrow$ 局部搜索”** 的马尔可夫链。模型不再需要靠运气背诵坐标，而是真正拥有了严谨的物理时空演绎能力。
