# 🚀 项目总览：Visual ToT 遥感多实体定位

## 一、 核心壁垒与升维打击点

* **旧痛点**：现有的遥感大模型面对复杂长句，采用“隐式黑盒推理”，模型极易在海量同类地物中发生“注意力漂移”，多实体精度随实体数量呈断崖式下跌。
* **新解法 (你的护城河)**：提出 **单次自回归下的视觉思维树 (Single-pass Visual ToT)** 范式。赋予模型类似人类的“宏观规划 -> 生成多候选区 -> 逐一校验排谬 -> 最终精确锁定”的高阶思维能力，并通过专门针对“搜索与剪枝过程”的 GRPO 强化学习，彻底激发大模型的自纠错潜力。

## 二、 核心技术栈

* **底座模型**：`Qwen2.5-VL-3B-Instruct` 或 `7B`。
* **数据合成外挂引擎**：`GPT-4o` (负责文本规划) + `Grounding DINO` (负责提取伪标签候选区)。
* **训练框架**：`LLaMA-Factory` + `vLLM`。

# 🧠 核心引擎 1：结构化输出与数据合成 (最难战役)

为了让模型学会这套复杂的思维范式，必须构建高度结构化的 Prompt 体系，并利用代码合成几千条高质量的“试错演绎”数据。

### 1. 状态机化输出结构定义 (XML风格)

强迫模型在输出最终答案前，必须完整经历以下四个生命周期：

1. `<plan>`：语义拆解与搜索层级规划。
2. `<stepX_propose>`：调用广度优先搜索，框出所有疑似候选区 (`<cand_i>`)。
3. `<stepX_verify>`：对候选区逐一校验，输出 `Pruned` (剪枝放弃) 或 `Proceed` (保留进入下一层)。
4. `<final_box>`：输出最终目标坐标。

### 2. SFT 黄金轨迹数据自动化合成脚本

（这是你的工作量重心，必须用 Python 脚本打通流水线）：

* **Step A (语义逆向)**：调用 LLM API，把 ME-RSRG 的指令（如“找四栋大厦旁边的高架桥下的加油站”）逆向拆解为层级规划。
* **Step B (视觉召回)**：调用 Grounding DINO，在图里把“四栋大厦”、“高架桥”的所有可能位置全部框出来（包括正确和错误的）。
* **Step C (逻辑编织)**：写一个规则引擎，生成一段“明知故问”的文本轨迹。比如让脚本故意先去看一个错误的候选区，生成一段“未发现高架桥，此分支废弃”的文字，然后再去看正确的候选区。将这套“完美试错过程”打包为 SFT 的 JSONL 训练集。

# 🎯 核心引擎 2：面向搜索树的定制化 GRPO 奖励函数

传统的计算最终 IoU 已经远远不够了。你的 Reward Function 必须是对一整棵“搜索树”进行打分。

$$R_{Total} = \lambda_1 R_{Plan} + \lambda_2 R_{Recall} + \lambda_3 R_{Pruning} + \lambda_4 R_{Final\_GIoU}$$

### 1. 语义规划奖励 ($R_{Plan}$)：防智障机制

* **逻辑**：检查 `<plan>` 里的层级是否包含指令中的核心实体词。
* **得分**：匹配成功给基础分 $0.5$，解析失败或错乱给 $-1.0$。

### 2. 候选区召回率奖励 ($R_{Recall}$)：鼓励广度探索

* **逻辑**：提取 `<step_propose>` 中所有的 `<cand_i>` 坐标。只要这堆框里，有一个框的区域**包含了/极其靠近**真实的 Ground Truth（或通过 DINO 提取的正确参照物），就给分。
* **得分**：召回成功给 $1.0$；如果模型连正确的边缘都没框到，说明“眼盲”，给 $-1.0$。

### 3. 自我剪枝验证奖励 ($R_{Pruning}$)：核心超车点

* **逻辑**：这是拉开你与 Baseline 差距的“神之一手”。奖励模型“自我否定”的能力。
* **机制**：
* 代码检测：模型是否对错误的 `<cand_i>` 输出了 `Pruned` (废弃) 标识？
* 代码检测：模型是否对正确的 `<cand_i>` 输出了 `Proceed` (保留) 标识？


* **得分**：**每成功正确剪枝一个干扰项，给予 $+2.0$ 的高额奖励！** 错误剪枝了正确答案，给予 $-2.0$ 惩罚。

### 4. 终极精度奖励 ($R_{Final\_GIoU}$)：物理对齐

* **逻辑**：计算最终 `<final_box>` 与真实目标的 Generalized IoU。
* **得分**：取值 $[-1, 1]$。

# 🛠️ 实施战术：四周冲刺计划 (Action Plan)

## Week 1：数据炼狱 (The Data Crucible)

* **目标**：不碰大模型训练，死磕数据合成流水线。
* **动作**：
1. 跑通 Grounding DINO 的本地推理代码。
2. 编写 Python 脚本联调 LLM 与 DINO，在 ME-RSRG 数据集上合成至少 3000-5000 条包含 `<plan>` 和 `<verify>` 逻辑的 ToT 轨迹数据。
3. **关键验证**：肉眼抽查 50 条生成的数据，确保逻辑连贯，没有把正确的框给错误地“剪枝”掉。



## Week 2：范式灌输 (Paradigm SFT)

* **目标**：让大模型学会“思考的格式”。
* **动作**：
1. 使用 LLaMA-Factory + LoRA 对 Qwen2.5-VL 进行监督微调。
2. 损失函数仅为标准的交叉熵。
3. **验收标准**：输入一张新图，模型不再直接吐答案，而是能字正腔圆地输出一堆 `<cand_i>` 和 `Pruned` 标签（虽然里面的坐标不一定精准）。



## Week 3：强化学习对齐 (The RL Forge)

* **目标**：让模型从“装模作样”变成“火眼金睛”。
* **动作**：
1. 编写包含四大项（Plan, Recall, Pruning, Final_GIoU）的 Python 奖励函数。重点处理复杂的正则解析与防崩溃机制。
2. 启动 GRPO 训练。
3. **核心关注**：死盯 TensorBoard 上的 $R_{Pruning}$ 曲线，确保模型真正学会了通过剪枝干扰项来获取高分。



## Week 4：降维打击与可视化 (The Execution)

* **目标**：用数据和视觉效果锤爆 Baseline。
* **定量指标**：跑出 $mAcc@0.5$ 指标。制作图表，对比你的“ToT-GRPO”与原始 ME-RSRG 的“普通 GRPO”在**包含 3 个实体以上**的极端复杂指令下的精度差异（必定是碾压态势）。
* **定性 Demo**：用 Gradio 写一个 UI。上传图片后，页面上能用动态的红绿框，直观展示模型“先全图框选 -> 红色叉掉错误区 -> 绿色锁定正确区 -> 最终画框”的完整思考过程。
